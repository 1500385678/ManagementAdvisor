## 一、设计原则

1. **端到端不分段**:本设计覆盖"飞书日历事件触发 → 4 API 拉数据 → LLM 5 段式抽取 → Markdown 推送飞书群 → 行动项转飞书任务"5 个环节,Phase 1 编码时不允许"只做一半"
2. **4.1 模板为入参契约**:本设计的所有 5 段式字段名/数据类型/必填规则严格沿用 4.1 模板,不允许"另起炉灶改字段名"
3. **4.2 4 API 为数据源契约**:本设计的 5 个环节中前 2 环节(触发 + 拉数据)的 API 端点/方法/参数严格沿用 4.2 文档
4. **降级显式化**:4.2 §5.5 边界汇总矩阵的 6 种会议类型,本设计显式标注每种类型的降级路径(全功能 / 警告标签 / 仅元信息)
5. **说话人映射必做**:4.2 §6.4 明确说话人映射是 Phase 1 必做项,本设计将其列为第 4 环节,不可跳过
6. **行动项闭环**:5 段式纪要生成后,行动项 4 字段(责任人/截止时间/优先级/状态)自动转飞书任务,闭环到 `lark task +create`
7. **可入库可复现**:数据流每个节点标注"输入/输出/责任人/失败兜底",Phase 1 编码时按节点落库,便于 dogfood 阶段对账

## 二、端到端数据流(5 环节 8 节点)

```
[飞书日历事件触发]
        │
        ▼
[节点 1 · 拉会议元信息] ─── 4.2 §2.1 calendar.v4.event.list / §2.2 vc.v1.meeting.list
        │
        ▼
[节点 2 · 拉参会人列表] ─── 4.2 §2.3 vc.v1.meeting.get_meeting_participants
        │
        ▼
[节点 3 · 拉转写]        ─── 4.2 §2.4 minutes.v1.transcript.get
        │
        ▼
[节点 4 · 说话人映射]    ─── 新增 API directory.user.get(4.2 §6.4 显式追加)
        │
        ▼
[节点 5 · 边界检测]      ─── 4.2 §5.5 边界汇总矩阵 6 类会议判定
        │
   ┌────┴────┐
   │ 全功能  │ 警告标签 / 仅元信息(降级)
   ▼         ▼
[节点 6 · LLM 5 段式抽取] ── 4.1 §二 5 段式骨架(背景/讨论要点/决策/行动项/风险)
        │
        ▼
[节点 7 · Markdown 渲染] ── 4.1 §五 Markdown 模板(人类可读)
        │
        ▼
[节点 8 · 推送 + 行动项闭环]
       ├─ 推飞书群:lark im +messages-send
       └─ 行动项 → 飞书任务:lark task +create(4 字段)
```

## 三、字段映射表(端到端)

> 扩展 4.2 §3.5 节"背景 7 字段映射",补充到 5 段式全字段。

### 3.1 段 1 · 背景(7 字段)

| 4.1 模板字段 | 数据来源 | 节点 | 备注 |
|---|---|---|---|
| 会议名称 | 4.2 §2.1 `summary` / §2.2 `meeting_topic` | 1 | 去除"会议""讨论"冗词 |
| 会议类别 | 推理:会议名关键词 + 邀请人 + 频次 | 6(LLM 推理) | 5 类:周会/月会/项目会/1v1/临时会 |
| 会议时间 | 4.2 §2.1 `start_time` / `end_time` | 1 | ISO 格式,本地时区 |
| 参会人 | 4.2 §2.3 `participants[].name` | 2 + 4 | speaker_id → 真实姓名 |
| 缺席人 | 邀请名单 - 实际参会人 | 2(差集) | 4.2 §3.5 "推理 + 飞书日历" |
| 会议目的 | 4.2 §2.1 `description` | 1 | 字段可能为空,空则由 LLM 推理 |
| 关联项目 | 推理:参会人部门 + 会议名 + 历史关联 | 6(LLM 推理) | 关联 OKR / 季度目标 |

### 3.2 段 2 · 讨论要点(动态字段)

| 4.1 模板字段 | 数据来源 | 节点 | 备注 |
|---|---|---|---|
| 议题 1-N | 4.2 §2.4 转写 `segments[]` 聚类 | 6(LLM 抽取) | 每议题 1 段,含主要观点 + 关键论据 |
| 共识 | 转写中"达成一致""同意"语句 | 6(LLM 抽取) | 与议题关联 |
| 分歧 | 转写中"反对""担心""但是"语句 | 6(LLM 抽取) | 与议题关联 |

### 3.3 段 3 · 决策(3 字段)

| 4.1 模板字段 | 数据来源 | 节点 | 备注 |
|---|---|---|---|
| 决策内容 | 转写中"决定""拍板""定了"语句 | 6(LLM 抽取) | 4.1 §2.3 决策 3 字段 |
| 决策人 | 转写中说话人 + 节点 4 映射 | 4 + 6 | 真实姓名 |
| 反对意见 | 转写中"X 反对""X 不同意"语句 | 6(LLM 抽取) | 若无人明确反对,记"无" |

### 3.4 段 4 · 行动项(4 字段必填 + 2 字段可选)

| 4.1 模板字段 | 数据来源 | 节点 | 备注 |
|---|---|---|---|
| 责任人(必填) | 转写中"@X 做""X 负责"语句 | 6(LLM 抽取) | 节点 4 映射真实姓名 |
| 截止时间(必填) | 转写中"X 月 X 日前""下周"语句 | 6(LLM 抽取) | 标准化为 ISO date |
| 优先级(必填) | 转写中"紧急""P0""尽快"关键词 | 6(LLM 抽取) | P0/P1/P2,缺省 P2 |
| 状态(必填) | 4.1 §2.4 行动项 4 字段规则 | 8(初始化) | 新建时 = "待开始" |
| 关联决策(可选) | 段 3 决策 ID 引用 | 6(LLM 关联) | 同段 3 决策 |
| 验收标准(可选) | 转写中"完成标准""交付物"语句 | 6(LLM 抽取) | |

### 3.5 段 5 · 风险(动态字段)

| 4.1 模板字段 | 数据来源 | 节点 | 备注 |
|---|---|---|---|
| 风险 1-N | 转写中"风险""担心""可能出"语句 | 6(LLM 抽取) | 每条含:风险描述 + 责任人 + 缓解措施 |
| 风险等级 | 4.1 §2.5 风险段规则 | 6(LLM 抽取) | 高/中/低,缺省中 |

### 3.6 3 类会议差异化字段(沿用 4.1 §三)

| 会议类别 | 段 1 背景追加 | 段 2 讨论要点追加 | 段 4 行动项数量 |
|---|---|---|---|
| 周会 | 同步项 / 上周遗留 | 5-10 个轻同步 | 2-5 条 |
| 月会 | 月度复盘数据 / 月度规划 | OKR 进展 | 5-15 条 |
| 项目会 | 需求评审 / 技术方案 | 评审意见 | 3-10 条 |

## 四、降级策略表(沿用 4.2 §5.5)

| 会议类型 | 触发条件 | 降级行为 | 推送形式 |
|---|---|---|---|
| 普通话 + 2-5 人 + 静音正常 | 默认 | 全功能 5 段式 | 完整 Markdown |
| 普通话 + 6-15 人 | 参会人 ≤ 15 | 全功能 + 说话人标记警告 | 完整 Markdown + 警告 |
| 普通话 + 16-50 人 | 参会人 ≤ 50 | 仅元信息(背景 7 字段) | 仅元信息 Markdown |
| 粤英混说 + 2-5 人 | 转写含方言关键词 | 全功能 + 方言警告 | 完整 Markdown + 警告 |
| 纯英文 | 英文占比 > 80% | 仅元信息 | 仅元信息 Markdown |
| 高噪音 + 多人 | WebRTC VAD 检测 | 仅元信息 | 仅元信息 Markdown + 降级提示 |

**降级兜底话术**(沿用 `_templates/飞书bot指令识别设计v0.1` §三 兜底话术 3 条):
- 无法识别:"本次会议类型超出纪要能力边界,仅生成会议元信息"
- 部分降级:"已生成 5 段式纪要,多人会议说话人标记仅供参考"
- 失败兜底:"会议纪要生成失败,已通知管理员,会议 ID: <meeting_id>"

## 八、不做什么

- **不写 LLM prompt**:本设计只规定 5 段式字段契约,具体 prompt 由 Phase 1 T2 算法起草
- **不写代码**:本设计是数据流 + 字段映射,所有节点留到 Phase 1 编码
- **不调 4 API 真机**:依赖 4.2 公开测试端点 mock 数据做字段映射草案,真机验证留到 Phase 1 启动步骤 2
- **不涉及 LLM 抽取规则**:沿用 4.1 §四 抽取规则(规则 + 关键词),LLM 抽取是 Phase 1 升级项
