# 飞书 bot 指令识别设计 v0.1

> Phase 0 第 5 项资产 · 2026-09-01 · T4 任务
> 范围:3 类核心指令(梳理流程 / 生纪要 / 诊断团队)+ 关键词表 + 意图映射 + 兜底话术
> 形态:纯规则 + 关键词表,不依赖外部凭证,Phase 1 真实开发可平移升级为 LLM 意图分类
> 后续:Phase 0 收尾时把规则表替换为向量检索 + LLM 兜底,作为 Phase 1 飞书 Agent 的对话入口

---

## 一、设计原则

1. **先有规则,后有 LLM**:v0.1 全部用关键词 + 正则匹配(可控、可解释、可入库),不调 LLM 分类;Phase 1 升级为 LLM 意图分类时,本表作为 fallback 兜底
2. **动词 + 名词组合**:每条指令至少 1 个动词(梳理/生成/诊断/看/查/出) + 1 个名词(流程/纪要/团队/状态/健康度),避免"光动词"或"光名词"误触发
3. **三意图正交**:3 类指令覆盖 Phase 1 三个核心模块(流程梳理器 / 会议纪要 / 健康度诊断),互不重叠,1 条消息只对应 1 个意图
4. **可入库可检索**:每条关键词是结构化字段(动词 / 名词 / 触发模式 / 优先级),可直接做匹配表

---

## 二、3 类核心指令 + 样例

### 指令 A:梳理流程(`process_map`)

**意图描述**:把口述或会议记录中的"团队怎么协作"梳理为流程图,支持与历史流程对比。

**用户样例(≥ 5 句)**:

1. "帮我梳理一下我们团队做需求评审的流程"
2. "把上周会议里说的报销流程画出来"
3. "我们现在新员工入职的流程是这样的:HR 介绍 → 部门对接 → 配环境 → 一周 buddy,帮我梳理下"
4. "看下我们组 bug 处理流程有没有断点"
5. "把今天聊的客户投诉处理流程整理成 Mermaid 图"
6. "梳理我们部门季度规划流程"
7. "画一下跨部门(产品-研发-销售)的项目交付流程"

**预期输出**:
- 流程图(Mermaid 格式,环节/责任人/输入输出/瓶颈标注)
- 文字描述(关键节点 + 责任人 + 周期)
- 与历史流程的 diff(若有)

---

### 指令 B:生纪要(`meeting_minutes`)

**意图描述**:基于会议录音/转写/议程,生成"纪要 + 决策 + 行动项 + 责任人 + 截止时间"五段式纪要,推送到飞书群。

**用户样例(≥ 5 句)**:

1. "生成本周周会的纪要"
2. "把这周的产品评审会纪要发到群里"
3. "今天和客户开的需求沟通会,帮我出纪要"
4. "上周五的项目复盘会纪要整理一下"
5. "把昨天 1v1 的会议内容生成纪要"
6. "我们月会的纪要什么时候能出来"
7. "上个月董事会纪要归档一下"

**预期输出**:
- 五段式纪要(背景 / 讨论要点 / 决策 / 行动项 / 风险)
- 行动项自动转飞书任务(若开启)
- 推送到指定飞书群(若指定)

---

### 指令 C:诊断团队(`team_health`)

**意图描述**:基于飞书协作数据(消息量/响应时长/任务完成率/请假模式/1v1 频次),产出团队健康度报告,标注风险信号。

**用户样例(≥ 5 句)**:

1. "看下我们组这周的健康度"
2. "诊断一下产品团队当前状态"
3. "我们部门最近是不是太累了,响应时长怎么样"
4. "出个月度团队健康度报告"
5. "看下隔壁组的状态如何"
6. "我们组响应时长这个月是不是变慢了"
7. "团队健康度评分给我看一下"

**预期输出**:
- 4 档风险分级(绿/黄/橙/红)
- 关键指标(消息量 / 响应时长 / 任务完成率 / 请假模式)
- 风险信号清单 + 建议动作

## 三、关键词表(动词 + 名词组合)

每类指令 ≥ 8 个触发关键词,优先级 P0-P2(数字越小优先级越高,冲突时 P0 胜出)。

### 指令 A:梳理流程

| 优先级 | 动词 | 名词 | 触发样例 |
|---|---|---|---|
| P0 | 梳理 | 流程 | "梳理下 XX 流程" |
| P0 | 画 | 流程图 | "画下 XX 流程图" |
| P0 | 整理 | 流程 | "把 XX 流程整理出来" |
| P1 | 出 | 流程 | "出个 XX 流程" |
| P1 | 流程梳理 | (隐含动词) | "XX 流程梳理" |
| P1 | 流程图 | (隐含动词) | "出流程图" |
| P2 | 画 | Mermaid | "画 Mermaid 图" |
| P2 | 流程断点 / 瓶颈 | (隐含动词) | "看流程有没有断点" |

**反例(不应触发)**:"流程很乱"(描述状态,非请求动作)

### 指令 B:生纪要

| 优先级 | 动词 | 名词 | 触发样例 |
|---|---|---|---|
| P0 | 生成 / 出 | 纪要 | "生成 XX 会议纪要" |
| P0 | 整理 | 纪要 | "把 XX 纪要整理一下" |
| P0 | 写 | 纪要 | "写份 XX 纪要" |
| P1 | 会议纪要 | (隐含动词) | "XX 会议纪要" |
| P1 | 归档 | 纪要 | "XX 纪要归档" |
| P1 | 出 | 会议记录 | "出份会议记录" |
| P2 | 复盘 | (隐含名词) | "帮我复盘一下" |
| P2 | 总结 | 会议 | "总结下今天的会" |

**反例(不应触发)**:"这个会议很重要"(描述,非请求)

### 指令 C:诊断团队

| 优先级 | 动词 | 名词 | 触发样例 |
|---|---|---|---|
| P0 | 诊断 | 团队 | "诊断下 XX 团队" |
| P0 | 看 | 健康度 | "看 XX 组健康度" |
| P0 | 出 | 健康度报告 | "出个月度健康度报告" |
| P1 | 看 | 状态 | "看下 XX 组状态" |
| P1 | 评估 | 团队 | "评估下 XX 团队" |
| P1 | 团队状态 | (隐含动词) | "XX 团队状态如何" |
| P2 | 协作数据 | (隐含动词) | "我们组协作数据怎么样" |
| P2 | 响应时长 | (隐含动词) | "响应时长有没有变慢" |

**反例(不应触发)**:"团队氛围不错"(描述,非请求)

## 四、意图映射表(关键词簇 → 处理函数)

| 意图 ID | 触发关键词簇 | 处理函数 | 必需参数 | 可选参数 |
|---|---|---|---|---|
| `process_map` | 梳理/画/整理 + 流程/流程图/Mermaid | `process_map_handler(text, context)` | `text`(口述或会议记录原文) | `compare_with`(历史流程 ID) / `format`(mermaid/drawio) |
| `meeting_minutes` | 生成/出/写/整理 + 纪要/会议记录;或 会议纪要/复盘/总结 + 会议 | `meeting_minutes_handler(meeting_ref, context)` | `meeting_ref`(会议 ID 或时间窗) | `push_to`(群 ID) / `auto_task`(bool) / `template`(五段式/简版) |
| `team_health` | 诊断/看/出 + 团队/健康度/状态;或 团队状态/响应时长 + 隐含动词 | `team_health_handler(team_ref, period, context)` | `team_ref`(团队 ID) | `period`(周/月/季) / `compare_with`(历史周期) / `push_to`(群 ID) |

**冲突处理**:
- 1 条消息只匹配 1 个意图:多意图时按 P0 优先级选择,P0 同级时按 A→B→C 顺序
- "看 XX 团队流程纪要"(混合意图)走 C(team_health),因 P0 诊断 > P1 流程梳理
- "出份上周周会纪要 + 诊断下我们组状态" 视为多轮对话,先回答前者再问后者

## 五、兜底话术(3 条)

### 5.1 无法识别(没有任何关键词命中)

> 抱歉,我没理解您的意思 😐
> 我现在能帮您做这 3 件事:
> 1. **梳理流程** — 例:"梳理下我们做需求评审的流程"
> 2. **生成纪要** — 例:"生成本周周会的纪要"
> 3. **诊断团队** — 例:"看下我们组这周的健康度"
> 您可以再说一次,或者直接点上面的例子。

### 5.2 参数缺失(命中意图但缺少必需参数)

> 收到啦 ✍️ 您是要"梳理流程",我需要更多一点信息:
> - **流程名称** — 例:"需求评审流程" / "新员工入职流程"
> - **流程内容** — 口述一段,或贴一段会议记录
> 给我这两项,我就帮您画出来。

### 5.3 多意图冲突(同时命中 ≥ 2 个意图且优先级并列)

> 我看您这条消息里有 2 个意思,先确认下您要哪个:
> 1. **梳理流程** — "梳理下我们组做 XX 的流程"(我理解您要这个?)
> 2. **生纪要** — "生成本周周会的纪要"
> 您可以直接回 "1" 或 "2",或者重新说一次您的主要需求。

## 六、Phase 1 升级路径

1. **短期(本周)**:本表作为 v0.1 规则版本,直接部署到测试群,收集 50 条真实 query

3. **长期(Phase 1 收尾)**:LLM 主分类 + 规则表兜底,准确率目标 ≥ 80%(Phase 0 验收标准)
