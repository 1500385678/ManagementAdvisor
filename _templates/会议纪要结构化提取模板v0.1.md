## 一、设计原则

1. **5 段式骨架固定**:5 段标题(背景/讨论要点/决策/行动项/风险)是结构化骨架,任何会议类别的纪要都必须包含这 5 段(类别差异在段内字段,不在骨架)
2. **行动项结构化优先**:行动项是纪要的核心交付物,必须 4 字段齐全(责任人/截止时间/优先级/状态),缺一不可;否则不算"结构化纪要",仅算"会议记录"
3. **决策可追溯**:每条决策必须记录决策人与反对意见(若有),确保未来回看时可还原决策过程,避免"谁拍板"模糊
4. **风险显式化**:风险段独立成段(不混在讨论要点中),便于 Phase 1 风险预警模块直接消费
5. **可入库可检索**:每条记录是结构化字段(不是叙述性段落),可直接入库;Markdown 形态是为了人类可读,JSON 形态是入库序列化形式
6. **抽取规则可解释**:v0.1 用规则 + 关键词抽取(可控、可入库),不调 LLM;Phase 1 升级为 LLM 抽取时,本规则表作为 fallback 与质检对照

## 二、5 段式纪要骨架

### 2.1 段 1 · 背景(BACKGROUND)

**目的**:让未参会者 30 秒内理解"这是关于什么的会议"。

| 字段 | 数据类型 | 必填 | 描述 |
|---|---|---|---|
| 会议名称 | string | 是 | 简短标题,≤ 30 字 |
| 会议类别 | enum: 周会/月会/项目会/1v1/临时会 | 是 | 决定段内字段差异化 |
| 会议时间 | ISO datetime | 是 | 例:`2026-09-09 14:00-15:30` |
| 参会人 | string[] | 是 | 列出全部参会者(姓名/花名) |
| 缺席人 | string[] | 否 | 缺席且需补会的同事 |
| 会议目的 | string | 是 | ≤ 100 字,1-2 句说清"为什么要开这个会" |
| 关联项目 | string | 否 | 关联的项目代号 / OKR / 季度目标 |

**抽取规则**:
- 会议名称:从会议邀请/议程标题提取,去除"会议""讨论"等冗词
- 会议类别:从会议名/会议目的关键词识别(详见 3. 节)
- 会议时间:从飞书日历 API 提取,标准 ISO 格式
- 参会人/缺席人:从飞书会议 API `get_meeting_participants` 提取

**占位示例**:
```
- 会议名称:XX 产品 9 月迭代评审
- 会议类别:项目会
- 会议时间:2026-09-09 14:00-15:30
- 参会人:张三、李四、王五(产品)、赵六(技术)
- 缺席人:钱七(已请假,会前提交书面意见)
- 会议目的:评审 9 月迭代的需求范围与技术方案,确认 9/15 上线节点
- 关联项目:OKR-2026Q3-O3 · 9 月迭代
```

### 2.2 段 2 · 讨论要点(DISCUSSION)

**目的**:记录会议中实质性讨论的内容(不是"谁说了什么",而是"讨论了什么、结论倾向是什么")。

| 字段 | 数据类型 | 必填 | 描述 |
|---|---|---|---|
| 议题编号 | int | 是 | 从 1 开始递增 |
| 议题标题 | string | 是 | 简短,≤ 30 字 |
| 讨论内容 | string | 是 | 200-500 字,记录"讨论了什么 + 主要观点 + 倾向性结论(若达成)" |
| 主持人 | string | 否 | 谁发起/主持该议题 |
| 时长 | int(分钟) | 否 | 该议题耗时 |

**抽取规则**:
- 议题切分:从原文"接下来讨论 XX""下面看 XX"等过渡语切分;若无显式切分,按"主要话题变化"自动切分(单议题不超过 30 分钟讨论时长)
- 讨论内容:用第三人称叙述,避免"张三说...李四反驳..."(这是会议记录,不是会议纪要);只保留"讨论了什么 + 倾向性结论"
- 倾向性结论:若讨论未形成决策但有方向,标注"(倾向 X,待决策)"

**占位示例**:
```
1. **9 月迭代需求范围**
   - 讨论内容:产品评审 5 个候选需求,讨论是否全部纳入 9/15 节点。倾向意见是 P0 需求 3 个全做,P1 需求 2 个砍掉 1 个、剩余 1 个顺延到 10 月(倾向,待决策)。
   - 主持人:王五
   - 时长:25 分钟
2. **技术方案:实时同步机制**
   - 讨论内容:对比 WebSocket 与长轮询两种方案,WebSocket 性能更优但需要服务端额外维护;长轮询实现简单但延迟高。倾向 WebSocket + 降级长轮询(倾向,待决策)。
   - 主持人:赵六
   - 时长:20 分钟
```

### 2.3 段 3 · 决策(DECISIONS)

**目的**:记录会议中**明确拍板**的决定(不是倾向性意见),每条决策可追溯到决策人。

| 字段 | 数据类型 | 必填 | 描述 |
|---|---|---|---|
| 决策编号 | int | 是 | 从 1 开始递增 |
| 决策内容 | string | 是 | ≤ 200 字,1-3 句说清"决定做什么/不做什么" |
| 决策人 | string | 是 | 拍板人(姓名/花名),可能多人但需明确主决策人 |
| 决策时间 | ISO datetime | 是 | 决策拍板的时刻(精确到分钟) |
| 反对意见 | string | 否 | 记录不同意见(若有),"X 反对,理由是 Y"格式 |
| 关联议题编号 | int | 否 | 关联的讨论要点议题编号 |
| 影响范围 | string | 否 | 该决策影响哪些团队/项目/后续工作 |

**抽取规则**:
- 决策识别:从原文"决定""确认""通过""拍板""就这么定"等动词识别;不包含"倾向""建议""下次再说"
- 决策人识别:从原文"X 拍板""X 决定""X 确认"等归属语识别;若多人共同决定,主决策人为职位最高者
- 反对意见:从原文"X 反对""X 不同意""X 担心"等语句提取;若无人明确反对,本字段记"无"

**占位示例**:
```
1. **9 月迭代仅做 3 个 P0 需求,2 个 P1 需求砍掉 1 个、顺延 1 个**
   - 决策人:王五
   - 决策时间:2026-09-09 14:35
   - 反对意见:钱七(缺席)会前提交书面意见"建议 2 个 P1 全部顺延",会议中李四支持钱七意见,但王五坚持保留 1 个,最终按王五意见执行
   - 关联议题编号:1
   - 影响范围:9 月迭代交付范围 / 10 月迭代排期
2. **实时同步采用 WebSocket + 长轮询降级方案**
   - 决策人:赵六
   - 决策时间:2026-09-09 15:10
   - 反对意见:无
   - 关联议题编号:2
   - 影响范围:服务端架构 / 客户端 SDK 升级
```

### 2.4 段 4 · 行动项(ACTION_ITEMS)

**目的**:把会议产出转化为**可执行的任务**,每条行动项 4 字段齐全,可直接对接飞书任务 API。

| 字段 | 数据类型 | 必填 | 描述 |
|---|---|---|---|
| 行动项编号 | int | 是 | 从 1 开始递增(全局唯一) |
| 行动项描述 | string | 是 | ≤ 200 字,以动词开头(做/出/写/改/确认...),避免"研究一下"等模糊动词 |
| 责任人 | string | 是 | 明确到人(姓名/花名),不接受"产品团队""技术组" |
| 截止时间 | ISO date | 是 | 精确到日,例:`2026-09-12` |
| 优先级 | enum: P0/P1/P2 | 否 | 缺省 P1 |
| 状态 | enum: 待启动/进行中/已完成/阻塞 | 否 | 缺省"待启动" |
| 关联决策编号 | int | 否 | 关联的决策编号(若行动项源自某条决策) |
| 验收标准 | string | 否 | 怎么算"完成"(交付物 + 通过条件) |

**优先级定义**:
- **P0** · 阻塞性:不完成会阻塞其他工作 / 客户已承诺的交付节点 / P0 需求
- **P1** · 重要:本周内必须完成,影响季度 OKR
- **P2** · 普通:本月内完成即可,无强阻塞

**状态流转**:`待启动 → 进行中 → 已完成`(若中途卡住走分支 → `阻塞`,需在备注中说明阻塞原因)

**抽取规则**:
- 行动项识别:从原文"X 负责 Y""X 在 Z 之前完成 W""接下来 X 做 Y"等归属语识别
- 责任人:必须是明确姓名,不接受"产品""技术"等团队名
- 截止时间:支持"下周三""9/15""月底"等口语化表达,需规范化转为 ISO date;无法规范化则标"待确认"并在备注中说明
- 优先级:从原文"紧急""P0""高优""尽快"等强度词识别;无强度词则 P1

**占位示例**:
```
1. **输出 9 月迭代 PRD v2(含 3 个 P0 + 1 个 P1 需求范围)**
   - 责任人:王五
   - 截止时间:2026-09-11
   - 优先级:P0
   - 状态:待启动
   - 关联决策编号:1
   - 验收标准:PRD 通过技术评审 + 需求池入库
2. **技术方案文档:WebSocket + 长轮询降级架构图 + 性能压测报告**
   - 责任人:赵六
   - 截止时间:2026-09-13
   - 优先级:P1
   - 状态:待启动
   - 关联决策编号:2
   - 验收标准:文档 + 压测报告 + 架构评审通过
3. **同步会议纪要到产品群 + 飞书任务**
   - 责任人:王五
   - 截止时间:2026-09-09
   - 优先级:P1
   - 状态:待启动
   - 关联决策编号:无
   - 验收标准:纪要推送成功 + 3 条行动项转飞书任务成功
```

### 2.5 段 5 · 风险(RISKS)

**目的**:把会议中识别出的风险**显式沉淀**(不混在讨论要点中),便于 Phase 1 风险预警模块直接消费。

| 字段 | 数据类型 | 必填 | 描述 |
|---|---|---|---|
| 风险编号 | int | 是 | 从 1 开始递增 |
| 风险描述 | string | 是 | ≤ 200 字,"如果 X 发生,则 Y"格式 |
| 风险等级 | enum: 高/中/低 | 是 | 基于"发生概率 × 影响范围"判定 |
| 责任人 | string | 否 | 谁负责跟进该风险(若指定) |
| 缓解措施 | string | 否 | 已约定的应对方案(若有) |
| 关联议题编号 | int | 否 | 关联的讨论要点议题编号 |

**风险等级判定**:
- **高** · 概率 ≥ 50% 且影响阻塞核心交付节点,或概率 < 50% 但影响范围 ≥ 2 个团队
- **中** · 概率 20-50% 或影响 1 个团队的核心工作
- **低** · 概率 < 20% 且影响可被个人消化

**抽取规则**:
- 风险识别:从原文"风险""担心""可能出问题""如果 X 怎么办""隐患"等关键词识别
- 风险等级:综合原文中"很大""严重""小概率"等强度词 + 责任人/影响范围的常识判定
- 缓解措施:从原文"我们的应对是 X""已经做了 X""计划 X"等语句识别

**占位示例**:
```
1. **WebSocket 服务端稳定性未验证,可能影响实时同步 SLA**
   - 风险等级:中
   - 责任人:赵六
   - 缓解措施:9/12 前完成压测,若不达标回退到长轮询
   - 关联议题编号:2
2. **9 月迭代排期偏紧,若 9/12 PRD 延迟将影响 9/15 上线**
   - 风险等级:高
   - 责任人:王五
   - 缓解措施:9/10 内部对齐 PRD 进度,若延迟则砍掉 1 个 P1 需求
   - 关联议题编号:1
```

## 三、3 类会议差异化字段

> 5 段式骨架固定(背景/讨论要点/决策/行动项/风险),但**段内字段在不同会议类别中差异化**:周会强调"同步+轻决策",月会强调"复盘+规划",项目会强调"评审+决策"。

### 3.1 周会

**特征**:高频(每周 1 次)、低决策密度(多同步)、行动项少(2-5 条)。

| 段落 | 必填字段 | 可选字段 | 差异说明 |
|---|---|---|---|
| 背景 | 会议名称/会议时间/参会人/会议目的 | 关联项目 | 周会目的通常简化为"同步本周进展 + 识别风险" |
| 讨论要点 | 议题编号/议题标题/讨论内容 | 主持人/时长 | 议题数 3-5 个,单议题 ≤ 15 分钟 |
| 决策 | 决策内容/决策人 | 其他 | 周会决策少(0-2 条),多数是同步而非决策 |
| 行动项 | 4 字段齐全 | 关联决策/验收标准 | 行动项 2-5 条,优先级多为 P1/P2 |
| 风险 | 风险描述/风险等级 | 缓解措施 | 周会风险多是"已知 + 待跟进",少有"突发" |

**周会特殊字段**(在"背景"段后追加):
- **上周行动项完成情况**:列出上周行动项编号 + 完成状态(已完成/进行中/阻塞/未启动)
- **本周重点**:本周 1-3 个最重要的事项

### 3.2 月会

**特征**:中频(每月 1 次)、高决策密度(规划+复盘)、行动项多(5-15 条)。

| 段落 | 必填字段 | 可选字段 | 差异说明 |
|---|---|---|---|
| 背景 | 会议名称/会议时间/参会人/会议目的 | 关联项目 | 月会目的通常是"复盘上月 + 规划下月" |
| 讨论要点 | 议题编号/议题标题/讨论内容 | 主持人/时长 | 议题数 5-10 个,单议题 ≤ 30 分钟 |
| 决策 | 决策内容/决策人/决策时间/反对意见/影响范围 | 关联议题 | 月会决策多(3-8 条),多涉及下月规划 |
| 行动项 | 4 字段齐全 | 关联决策/验收标准 | 行动项 5-15 条,优先级覆盖 P0/P1/P2 |
| 风险 | 风险描述/风险等级/责任人 | 缓解措施 | 月会风险多是"跨团队/跨项目"层面 |

**月会特殊字段**(在"背景"段后追加):
- **上月关键指标回顾**:OKR 完成率 / 关键项目里程碑 / 客户满意度 / 团队健康度
- **下月规划重点**:下月 3-5 个最重要的项目/目标
- **资源调整**:人力/预算/工具的调整说明(若有)

### 3.3 项目会

**特征**:项目制(每个项目 N 次)、高评审密度(技术方案/需求评审)、决策多。

| 段落 | 必填字段 | 可选字段 | 差异说明 |
|---|---|---|---|
| 背景 | 会议名称/会议时间/参会人/会议目的/关联项目 | 缺席人 | 项目会必须明确"评审哪个项目的什么内容" |
| 讨论要点 | 议题编号/议题标题/讨论内容 | 主持人/时长 | 议题数 3-8 个,可能是多项目并行评审 |
| 决策 | 决策内容/决策人/决策时间/反对意见/影响范围 | 关联议题 | 项目会决策多是"通过/不通过/需修改" |
| 行动项 | 4 字段齐全 | 关联决策/验收标准 | 行动项 3-10 条,关联到具体需求/技术方案 |
| 风险 | 风险描述/风险等级/责任人 | 缓解措施/关联议题 | 项目会风险多是"技术/进度/资源" |

**项目会特殊字段**(在"背景"段后追加):
- **项目阶段**:启动/规划/执行/监控/收尾
- **评审材料清单**:本次评审的 PRD/技术方案/原型/数据报告等(列出文件名 + 版本)
- **下次评审节点**:下次评审时间 + 评审内容(若已知)

## 四、抽取规则细则

### 4.1 行动项 4 字段规则

| 字段 | 抽取关键词/模式 | 缺省处理 | 异常处理 |
|---|---|---|---|
| 责任人 | "X 负责""X 在...前完成""接下来 X 做""请 X" | 必须显式提取,不接受"团队""组" | 若模糊(如"产品看一下")→ 标"待确认" + 备注 |
| 截止时间 | "X 月 X 日前""下周三""月底""本周内""9/15" | 标"待确认" | 若口语化无法转 ISO → 标"待确认" + 备注原话 |
| 优先级 | "P0""紧急""高优""必须""尽快" → P0;"P1""重要""应该" → P1;其余 → P2 | P1 | 无 |
| 状态 | 仅在"复盘型"会议中提取(上周/上月行动项回顾) | 待启动 | 若会议中提及"已完成""进行中"等状态,标对应值 |

**强校验规则**(Phase 1 自动化用):
- 若行动项缺"责任人"或"截止时间",纪要不算"结构化纪要",仅算"会议记录",Phase 1 飞书任务转 API 不会调用
- 若行动项含"看一下""研究一下""讨论一下"等模糊动词,Phase 1 自动追加"⚠️ 模糊动词"标记,需责任人 24h 内补充明确动作

### 4.2 决策 3 字段规则

| 字段 | 抽取关键词/模式 | 缺省处理 |
|---|---|---|
| 决策内容 | "决定 X""确认 X""通过 X""拍板 X""就这么定 X" | 必须显式 |
| 决策人 | "X 决定""X 拍板""X 确认""X 同意" | 缺省 = 会议主持人 |
| 反对意见 | "X 反对""X 不同意""X 担心""X 建议" | 缺省 = "无" |

**强校验规则**:
- 决策内容若与讨论要点高度重合(> 80% 文本相似),视为"未决策",不进入决策段
- 决策人若为多人(> 3 人)且无明确主决策人,标"集体决策"并在备注中说明分歧

### 4.3 风险字段规则

| 字段 | 抽取关键词/模式 | 缺省处理 |
|---|---|---|
| 风险描述 | "风险""担心""可能出问题""如果 X""隐患" | 必须显式 |
| 风险等级 | "很大风险""严重""高优" → 高;"可能""担心" → 中;"小概率""低概率" → 低 | 中 |
| 缓解措施 | "应对是 X""已做 X""计划 X""兜底 X" | 缺省 = "无" |

## 六、Phase 1 升级路径

1. **短期(1-2 周)**:本模板作为 v0.1 规则版本,直接给 T2 业务窗口使用,收集 10 份真实会议纪要验证模板完整度
2. **中期(2-4 周)**:用 10 份真实纪要训练 LLM 抽取器,本模板降级为 fallback 与质检对照(LLM 抽取字段缺失时用规则补)
3. **长期(Phase 1 收尾)**:LLM 主抽取 + 规则 fallback,行动项自动转飞书任务(对接 lark-cli task API),准确率目标 ≥ 80%(Phase 0 验收标准)
4. **与其他模块对接**:
   - 行动项 → 飞书任务 API(`lark-cli task +create`)
   - 风险 → 健康度诊断模块(`_rules/健康度诊断规则v0.1.md` 的"高风险信号"维度)
   - 决策 → 管理方法论沉淀(`_index/主题速览.md` 的"原则"标签)
